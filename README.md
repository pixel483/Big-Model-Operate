# AI 应用开发转岗资料包

给「学过 Python 基础但手生、目标转岗 AI 应用开发」的人。按 `16-week-plan.md` 走，约 4 个月。

## 目录

| 文件 | 什么时候用 | 内容 |
|---|---|---|
| `16-week-plan.md` | **现在就读一遍** | 16 周按周计划、每周验收标准、面试考点、简历写法、易放弃节点 |
| `python-refresh.md` | 第 1–2 周 | 只补大模型开发用得到的 10 个 Python 知识点 + 7 天恢复练习 + 自测清单 |
| `first-project/` | 第 6 周（也可提前跑） | 第一个能跑的项目：个人文档问答助手（RAG 最小实现，零框架） |

## 今天就能做的三件事

1. 读 `16-week-plan.md` 的「先看清目标岗位」和「阶段一」，确认路线符合预期。
2. 建一个 GitHub 仓库，名字随意（比如 `ai-learning-log`），**从今天起所有练习都往里放**。转岗时这就是你的第一份作品集。
3. 按 `python-refresh.md` 的 D1 写第一个脚本，push 上去。

## 关于第一个项目

`first-project/` 刻意不用 LangChain、不用向量库、不用数据库，只依赖三个轻量包。目的是让你**看清 RAG 每一步在干什么**：文档怎么切、检索怎么算分、上下文怎么拼进 prompt、模型怎么被调用、出处怎么标注。

跑通之后再逐块替换成生产级组件（Chroma + bge-m3 + Reranker + FastAPI），这个「从裸实现到工程化」的过程，本身就是面试里最好讲的故事。

## 一条提醒

计划里的周数是节奏参考，不是考试期限。卡住很正常，尤其是 W2（环境）、W7（检索效果）、W9（Agent 跑飞）。**宁可某一周多花一倍时间把东西真正跑通，也不要为了赶进度跳过动手环节。**
